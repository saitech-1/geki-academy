# Implementation status

Verified October 20, 2026. Baseline versions: Next.js 16.4.2, React 19.3.1, Express 5.3.0, Firebase web 13.0.0, Firebase Admin 14.5.0, Prisma 7.10.1, TypeScript 5.9.3. Exact resolved dependencies are in `package-lock.json`.

## Verification

- TypeScript checks and production build pass.
- Six domain tests pass: membership boundaries, unique watched coverage, quiz grading and reminder windows/renewals.
- Fourteen integration scenarios pass against the running API, Firebase Auth Emulator and real local PostgreSQL. Coverage includes concurrent device registration, stream transfer/revocation, protected media, subtitle publication, membership expiry, role isolation, persisted preferences and learning records.
- Four reminder integration checks pass: concurrent deduplication, Burmese copy, renewal suppression and suspended-user suppression.
- Browser checks confirm saved language choice survives reload, Burmese navigation renders and the tested mobile page has no horizontal overflow.
- Cloud Prisma migration history is fully baselined, schema comparison reports no difference and deployment/security commands succeed with the separate migration login.
- Admin API checks pass for course/section/lesson/video CRUD, file validation, private preview ranges, tamper rejection, deletion guards, source cleanup and audit records.
- Admin browser checks pass for create/edit/delete course and upload/preview/edit/delete video. Dialogs center at 1024, 1280 and 1440 widths. Motion and reduced-motion checks pass without browser errors.
- One-time owner invitation checks pass: exact verified email only, concurrent single grant and no automatic re-elevation after subsequent role changes. The real owner invitation is configured; it is accepted only after the matching Firebase sign-in.
- Chrome browser checks pass: admin/student sign-in, responsive dashboard/device pages, native video playback, resume after reload, quiz submission and dashboard persistence. No page errors or horizontal mobile overflow were observed in those checks.
- Production API health and catalog queries reach the new Supabase database through verified TLS. All 18 application tables have RLS; Supabase's security advisor reported no notices after provisioning. There are no public application-table grants.
- Real Firebase project's public configuration endpoint responds successfully and authorizes `localhost`. A real user's email delivery, Google popup and production privileged Admin credentials remain unverified.
- Production dependency audit reports zero known vulnerabilities after pinning the patched transitive gRPC dependency. Development-tool advisories are tracked separately by `npm audit`.
